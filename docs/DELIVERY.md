# 笔试交付说明

## 产品判断

这个 Agent 服务于海外 AI 产品的内容与增长工作。它不把热点直接搬运到 X，而是先判断事件和账号定位的关系，再生成供人工审核的候选内容。

## 技术交付

- 本地 FastAPI 服务，`uvicorn app:app --reload` 启动。
- SQLite 记录来源、文章、事件、候选、审核动作和运行记录。
- 海外和国内两组各三个公开 RSS/Atom 来源，具有独立超时、有限重试和错误记录；国内组用于海外来源不可访问时的替代输入。
- 可选 Tavily Search 数据 API 补充最近一周新闻，保留原始网页来源并与 RSS 一起去重、抽取正文和聚类；API 失败不阻断扫描。
- 实时文章正文按 URL 去重抽取，失败时保留 RSS 摘要；候选显示内容质量分和风险标记。
- 运行记录展示每个来源的成功/失败、重试、耗时、正文回退和演示回退状态。
- 每日自动扫描默认关闭，可配置北京时间、来源模式和开关；同一日期只运行一次，成功/失败与关联运行编号独立留痕。
- 固定演示快照保证无网络、无 AI API 时仍能演示。
- 扫描入口提供“演示快照”“海外 RSS / Atom”“国内 RSS / Atom”三个独立选项；国内组默认使用 36氪、少数派和 IT之家。
- HN RSS 元数据会转换为可读英文摘要；确定性候选文案限制在 280 字符内。
- 真实 RSS/Atom 需要由具有出站 HTTPS 权限的本机 Python/uvicorn 进程执行。若网络使用代理，可设置 `HTTP_PROXY`/`HTTPS_PROXY` 或写入本地 `.env`；每次扫描会按当前环境重新连接并独立重试来源。`WinError 10013` 表示 Python 进程的 socket 被系统安全策略拒绝，应检查防火墙/安全软件出站规则或改用普通本机终端启动，不应通过反复开关 VPN 解决。
- 可双击根目录 `start_agent.bat` 一键启动；它会检查虚拟环境、初始化缺失的 `.env`、预检 Python HTTPS、避开占用端口、等待 `/health` 后打开候选内容池。防火墙只检查并提示，不自动修改系统规则；也可使用 `scripts/start_agent.ps1 -CheckOnly` 单独诊断。
- 侧栏左下角提供本机“模型、数据与调度”配置入口，密钥不回显；顶部人工终审入口直接处理候选一。
- 确定性模板是正式默认路径；OpenAI 兼容 API 可读取受限来源正文，生成优化标题与摘要、提供 `-10..+10` 的有界选题调整、内容增强和智能初审。AI 通过项进入候选一，人工通过或修改后进入候选二。
- 智能审核保存结论、理由和置信度；通过必须达到可配置门槛。未通过或超过本轮额度的条目不进入候选一；未配置或调用失败时明确标为规则兜底。
- OpenAI 兼容成功路径通过本地 HTTP 合约测试验证 SDK 请求、JSON 解析、限长和 SQLite 持久化；这项测试不冒充外部模型质量评估。
- 账号画像参与优先级判断；审核结果会以可解释、有限幅度的规则调整下一轮排序。
- HN 公开 points/comments 作为真实热度信号进入基础优先级；没有公开互动量的来源不生成模拟热度。来源可信度以独立分数直接进入基础公式。
- 独立 `relevance_score` 由现有关键词、关注/回避主题和风险规则模拟，输出明确的“推荐 / 不推荐”与理由，不调用大模型。
- 已采用候选支持可恢复删除，审核历史和反馈数据继续保留。

## AI 与人工分工

确定性代码负责来源清洗、文本相似度聚类、真实热度归一化、来源可信度与基础评分、独立相关性、反馈评分、跟进判断和基础英文文案。可选 AI 对有限数量的初筛热点整理标题与摘要，提供有界选题调整、内容增强和第一重智能审核；它不负责聚类、基础评分、规则相关性、人工终审或发布。人工对候选一负责第二重事实核验、账号相关性、品牌语气和合规风险检查，通过或修改后进入候选二。

## UI 设计理念

- 使用安静、紧凑的运营工作台，而不是营销落地页，便于内容人员反复扫描和审核。
- 候选列表优先支持横向比较；详情页按“判断、核验、操作”组织信息。
- 最终分、风险和跟进建议先展示，评分构成与次要来源渐进展开，减少首屏噪声。
- 页面明确展示“采集整理 → AI 初审候选一 → 人工终审候选二”，审核区支持保存后进入下一条；移动端将审核操作提前并避免界面重叠。
- 所有关键操作保留服务端表单语义，JavaScript 不可用时仍能完成扫描和审核。

## 真实案例

[`REAL_E2E_CASE.md`](REAL_E2E_CASE.md) 记录了一次两轮真实扫描历史快照：三类来源共 60 条输入，人工采用候选后，其反馈调整从 `0` 变为 `+10`，最终分从 `74` 升至 `84`，排名从第 6 升至第 2。当前公式已增加真实热度和来源可信度，重新运行脚本会按实时 feed 输出新的分值。

## 当前限制

- 正文抽取是最佳努力能力，部分候选仍需要人工打开原文核验。
- 来源站点和中转 API 可能临时限流或超时；系统会记录错误并保留其他来源结果。
- 反馈适配使用可解释规则和时间衰减，不等同于机器学习；少量反馈可能不足以代表长期偏好。
- 文本聚类是确定性相似度规则，不宣称使用语义模型；高度改写的同一事件仍可能需要人工合并判断。
- 未配置外部 API Key 时所有候选使用确定性模板和规则初筛兜底；该路径可演示，但不代表完成真实 AI 审核。
- 模型与 Tavily 都会产生外部 API 调用成本和延迟；默认每轮最多评估 12 条候选、补充 10 条数据结果，可在本机配置页关闭。
- 每日自动扫描依赖 FastAPI 服务持续运行；服务在计划时刻关闭时，当前版本不提供系统级唤醒或错过任务补跑。
- 本版本不自动发布、不做多用户权限，也不宣称自动训练推荐模型。

## 继续优化优先级

优先继续评估聚类准确率、候选文案采用率和正文抽取质量，并用更多人工审核样本校准反馈上下限。完成仓库与演示交付后，再评估 X 来源或其他数据源扩展。
