# Product Requirements

## Product Outcome

为面向英语市场的海外 AI 产品官方账号建立一个双重审核候选池：系统从公开热点中发现事件、合并重复信息、整理标题与摘要，经过 AI 初审进入“候选一”，再由人工终审进入“候选二”，最终决定权保留给人工。

## Primary User

内容与增长人员需要反复处理新闻、官方公告和社区趋势。他们需要看到来源、事件判断、评分理由、风险提示和文案草稿，而不是一个直接自动发布的黑盒推荐器。

## Acceptance Criteria

- 用户可以运行演示快照、海外 RSS/Atom 扫描或国内 RSS/Atom 扫描；三种输入模式彼此独立。
- 国内输入模式默认读取 36氪、少数派和 IT之家，作为海外来源网络不可用时的替代来源组。
- 候选池提供“全部 / 国内来源 / 海外来源 / 演示快照”来源分类标签页；“全部”视图也必须按三类拆成独立候选区块，各区块显示数量并在组内按最终优先级排序。
- 每条候选事件在列表和详情中明确标记为国内来源、海外来源或演示快照；真实扫描全部失败并回退时标记为演示快照。
- 三类来源可被统一展示，重复文章归并为候选事件。
- 用户可以开启或关闭每日自动扫描，设置北京时间执行时刻和演示/海外/国内来源模式；系统每天最多自动执行一次，并记录成功、失败和关联运行结果。
- Hacker News 的结构化元数据不得以裸 URL 和字段标签直接进入事件摘要或候选文案；无 AI Key 时也必须生成可读、可审核且不超过 280 字符的英文候选文案。
- 每条候选显示基础分、账号画像调整、反馈调整、模型调整、最终分、跟进判断、来源和风险提示；模型非零调整必须显示理由和置信度。
- 基础优先级明确包含时效性、主题信号、多来源验证、真实热度和来源可信度；没有公开互动数据时显示“暂无热度信号”，不得用模拟数值冒充真实热度。
- Hacker News 条目保留公开 points/comments 并转换为标准化热度；来源可信度作为独立可见分数直接参与基础优先级。
- 每条事件输出独立 `relevance_score` 和明确的“推荐 / 不推荐”结论及理由；当前版本由账号关注/回避主题、AI 领域关键词和风险规则模拟，不调用大模型。
- 每条候选显示内容质量分、正文抽取状态和正文不可用时的 RSS 摘要回退提示。
- 配置模型后，系统读取有限数量热点的来源标题、摘要和可用正文片段，生成独立的优化标题、事实摘要、内容角度和英文文案；原始来源内容始终保留用于核验。
- 智能审核必须给出通过或不通过结论、理由和置信度；只有明确通过且达到配置门槛的热点进入“候选一”，未通过或未进入本轮模型额度的热点单独展示且不能直接提交人工终审。
- “候选一”只承载等待人工终审的 AI 初选结果；人工选择“通过”或“修改后通过”后进入“候选二”最终候选池，人工驳回项单独保留。
- 用户可以填写受众、关注主题、回避主题、语气和补充说明；旧的 `profile` 输入仍可使用。
- 用户可以通过、修改或驳回候选，并保存英文文案与审核意见。
- 审核详情优先展示推荐结论、内容质量和风险，评分构成与次要来源按需展开；用户可以仅保存当前结果，也可以保存后连续处理下一条高优先级待审核候选。
- 顶部“人工终审工作区”显示候选一数量，点击后直接打开最终优先级最高的待人工终审候选。
- 左下角提供“模型、数据与调度”配置入口，显示模型智能处理、数据补充和每日自动扫描是否启用；API Key 不在页面中回显。
- 用户可配置 OpenAI 兼容模型 API，并分别控制选题评分、内容整理和智能审核，设置每轮处理数量与审核置信度门槛；选题调整限制在 `-10..+10`。
- 用户可配置 Tavily Search 作为真实扫描的补充数据 API；补充结果保留原始来源链接，数据 API 失败不阻断 RSS 扫描。
- 用户可以删除已采用候选，并在“已删除”列表中恢复；删除不得破坏来源、审核历史或反馈记录。
- 下一轮扫描会以有限、可解释的规则使用历史审核反馈。
- 没有网络或 API Key 时仍能完成端到端演示。
- 真实扫描结束后，候选池必须明确反馈真实来源是否成功；全部来源失败并回退演示数据时，显示失败原因、失败来源和运行记录入口。
- 可选 AI 不得成为采集、聚类、基础评分或离线演示成功的必要条件；模型未配置或调用失败时，候选明确标为“规则初筛兜底”，允许人工继续演示，但不得冒充已经完成 AI 审核。
- 运行记录能够区分手动/自动触发，查看来源成功/失败、重试、耗时、正文回退和演示回退状态；自动扫描另有成功/失败结果历史。
- 候选池、候选详情和运行记录使用一致的紧凑仪表盘界面；桌面侧栏可折叠并记忆用户选择，移动端导航不遮挡主要操作。
- 扫描、审核、删除和恢复操作提供清晰的悬停、焦点、按压和处理中反馈，同时保持原有表单字段、结果与跳转行为。

## Product Boundaries

- 不自动发布到 X。
- 不把规则式反馈调整称为自动训练或机器学习。
- 当前版本不承诺多用户权限、向量数据库或多智能体协作。


## Chat Demo Extension

- 候选池提供自然语言任务入口；用户提交需求后，系统先返回结构化计划，确认后执行。
- 任务计划至少保存查询、来源模式、时间范围、输出类型、账号画像和确认状态。
- 演示默认使用明确标注的固定快照；真实 RSS / Atom 与数据 API 模式继续保留为能力验证入口。
- 模型不可用时必须显示规则解析和演示快照回退提示，不能把回退结果标记为实时模型执行。
- 聊天任务完成后仍进入现有候选一、人工终审和候选二流程；不推荐和 AI 未通过事件继续保留。
