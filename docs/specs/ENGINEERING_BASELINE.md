# Engineering Baseline

本文档记录当前实现必须满足的工程契约。产品意图和技术决策原因分别见 [`../requirements/PRODUCT_REQUIREMENTS.md`](../requirements/PRODUCT_REQUIREMENTS.md) 与 [`../technical/ARCHITECTURE.md`](../technical/ARCHITECTURE.md)。

## Runtime Contract

- 应用使用 FastAPI、Jinja2 和 SQLite，不引入独立前端工程。
- 界面资源必须从本地静态目录加载，不依赖 CDN、外部字体或运行时前端构建；核心导航和表单在 JavaScript 不可用时仍可使用。
- 本地入口是 `app.py:app`，标准启动方式是 `uvicorn app:app --reload`。
- `GET /health` 返回服务状态；无网络和无 AI API Key 时仍必须可完成演示扫描。
- FastAPI lifespan 启动每日调度检查；调度默认关闭，启用后按北京时间和配置时刻执行，应用未运行时不承诺补跑。

## Pipeline Contract

扫描按以下顺序处理：RSS 与可选数据 API 抓取、标准化、去重、事件聚类、基础优先级评分、账号画像调整、历史反馈调整、跟进判断、有限候选模型整理与智能审核、重新排序、候选一人工终审、候选二归档。

HN 标准化结果不得把 `Article URL`、`Comments URL`、`Points` 或 `# Comments` 字段串直接写入事件摘要或候选文案。同一来源的固定摘要句式不得单独触发事件合并；事件摘要最多汇总三个去重后的高可信来源摘要。

基础分由 `时效 0..30 + 主题信号 0..25 + 不同来源验证 0..15 + round(heat_score * 0.15) + round(credibility_score * 0.15)` 构成并限制在 `0..100`。多源验证按不同 `source_name` 计算；来源可信度按官方公告 `92`、媒体新闻 `80`、社区趋势 `65`、数据检索 `60` 映射后按不同来源取平均。没有真实互动量时 `heat_score=0`，不得生成模拟互动数据。

事件最终分为 `base_score + profile_adjustment + feedback_adjustment + model_adjustment`，最终值限制在 `0..100`。画像和反馈调整都有固定上下限；模型选题调整限制在 `-10..+10`，且非零调整必须附带理由，不能改写基础分。

独立相关性分由确定性规则计算：`10 + min(60, AI 领域关键词数 * 12) + min(30, 关注主题命中数 * 15) - min(50, 回避主题命中数 * 25)`，结果限制在 `0..100`。分数达到 `45` 且未命中回避主题或未经证实风险时输出“推荐”，否则输出“不推荐”；该结论不得读取或继承模型调分。

## Persistence Contract

SQLite 至少保留 `sources`、`articles`、`events`、`candidates`、`review_actions` 和 `runs` 六类核心对象，并维护事件与文章、候选与运行记录的关联。

`events` 保存 `base_score`、`profile_adjustment`、`feedback_adjustment`、`model_adjustment`、模型理由和置信度，以及 `heat_score`、`credibility_score`、`relevance_score`、推荐结论和理由；`candidates` 保存优化标题、优化摘要、AI 审核状态、审核理由和审核置信度；`runs.profile_json` 保存本次使用的账号画像，`runs.trigger_type` 区分手动与自动触发。`app_settings` 保存本机 API 和调度配置。数据库初始化必须通过缺失列检查和增量 `ALTER TABLE` 兼容已有数据，不得删除已有候选、运行或审核记录。

`articles` 保存正文、正文来源、抽取状态、抽取错误、内容质量标记、真实互动量和标准化热度；正文抽取失败时必须保留 RSS 摘要作为回退内容。`events` 保存事件级内容质量分和质量风险标记。`runs` 保存来源统计、耗时和是否使用演示回退。`scheduled_scans` 以北京时间日期唯一防重，保存计划时刻、状态、关联 `run_id` 和错误；当天修改执行时间不得触发第二次自动扫描。

候选列表与详情必须根据关联运行记录展示来源分类：`domestic` 为“国内来源”，未回退的 `live` 为“海外来源”，`demo` 或设置了 `fallback_used` 的真实扫描为“演示快照”。候选池默认按国内、海外、演示三类分成独立区块，并支持来源分类筛选；状态筛选与来源筛选可以组合使用。

已采用候选使用 `candidates.deleted_at` 软删除；普通列表不显示软删除候选，“已删除”列表允许恢复。软删除不得清理事件、文章、审核动作或反馈信号，后续扫描不得自动恢复已删除候选。

## Source Resilience

- 来源配置提供海外和国内两个独立预设；每个预设包含三个公开来源输入，并在运行记录中保留所选来源组。
- 国内预设当前包含 36氪、少数派和 IT之家，海外预设当前包含 TechCrunch AI、OpenAI News 和 Hacker News AI。
- Hacker News RSS 中公开的 points/comments 是当前真实互动热度信号，按对数尺度标准化到 `0..100`；其他没有公开互动量的来源明确保留为无热度信号。
- 配置 Tavily Search 后，真实扫描最多补充十条最近一周新闻；每条结果保留原始网页链接并以“数据检索”来源类型进入统一流水线。数据 API 失败不得阻断 RSS 或演示回退。
- RSS/Atom 来源逐个请求，具备独立超时、有限重试和退避。
- 单个来源失败不得阻断其他来源；错误要写入运行记录。
- 所有真实来源失败或没有输入时切换固定演示快照。
- 真实抓取进程必须具备出站 HTTPS 权限；HTTPX 使用当前 `HTTP_PROXY`/`HTTPS_PROXY` 环境配置，每次扫描重新建立连接。运行环境拒绝 socket（例如 Windows `WinError 10013`）时，应由部署环境修复出站规则，不得把该错误误判为来源内容不可用。
- 正文抽取按文章 URL 去重并优先读取 SQLite 缓存；实时扫描每个来源最多并行抽取 5 篇正文，其余保留 RSS 摘要；单篇正文失败不得阻断其他文章或候选生成。
- 来源运行统计至少记录成功数、失败数、重试次数、耗时和回退状态。

## AI And Publishing Boundary

- 确定性模板是正式默认内容路径，英文候选文案不得超过 280 字符。OpenAI 兼容 API 可用于受限选题调整、中文标题与摘要整理、增强角度和英文文案、补充风险及智能初审；未配置或调用失败时继续使用确定性结果并明确标为规则兜底。
- AI 不参与来源清洗、文本聚类、基础评分、画像评分或反馈评分。模型只处理确定性初筛后的有限数量热点，调整分限制在 `-10..+10`；无理由的非零分必须归零，模型风险不得删除规则风险。
- 智能审核输出必须限制为通过或不通过，并保存理由与 `0..100` 置信度；通过结论只有在理由非空且置信度达到配置门槛时有效。模型输出缺失、越界或低于门槛时不得进入 AI 通过状态。
- AI 审核通过项与明确的离线规则兜底项可进入候选一；模型已配置时，超过每轮模型额度的条目必须标为未评估且不得进入候选一。规则兜底必须在列表和详情提示未完成真实 AI 审核。
- 模型与数据 API 密钥只保存在本机环境或 SQLite 配置表中，不得回显到页面、写入运行记录或日志。配置页留空时保留已有密钥，并提供显式删除选项。
- 审核反馈使用可解释的规则调整，不进行自动训练。
- 系统不自动发布到 X，不引入多智能体、向量数据库或权限系统。

## Review Workflow Contract

- `status=pending` 只返回 AI 审核通过或规则兜底的候选一条目；`status=final` 合并人工采用与人工修改后的候选二条目；`status=ai_filtered` 返回 AI 未通过或本轮未评估条目。
- AI 未通过或未评估的待处理条目不得直接调用人工审核接口；人工采用或修改后进入候选二，人工驳回保持独立状态。
- 审核提交必须兼容未提供连续审核字段的旧调用；缺省行为是保存后返回当前候选详情。
- `next_action=next` 保存成功后必须进入 `/review/next`，由该入口选择最终优先级最高的剩余待审核候选；队列为空时返回待审核列表。
- 提交反馈脚本在禁用按钮防止重复提交前，必须保留触发按钮的名称和值，不能改变 `next_action` 或其他提交按钮的服务端语义。


## Chat Task Contract

- 聊天任务必须先保存用户消息和结构化计划，再允许确认执行。
- 确认接口只允许从 waiting_confirmation 原子转换到 queued，重复确认不得重复启动扫描。
- 后台任务必须在独立数据库连接中复用现有扫描流水线，并持久化最终状态、运行编号、进度标签和错误。
- 无模型 Key、模型调用失败或结构化输出无效时，必须明确标记规则回退并使用演示快照；不得伪装为实时模型结果。
- 聊天入口不能绕过 AI 门禁、人工终审、软删除或反馈留痕规则。
